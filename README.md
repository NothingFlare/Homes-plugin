## Установка

1. Кинуть homes-plugin.jar в plugins/ на Paper 1.20.x+.
2. Рестарт/reload сервера.
3. Данные хомов хранятся в plugins/HomesPlugin/homes.yml.

## Структура homes.yml

```yaml
<uuid игрока>:
  <название хома>:
    world: world
    x: 123.0
    y: 64.0
    z: -456.0
    yaw: 90.0
    pitch: 0.0
```

## Команды

| Команда              | Описание                                 |
|----------------------|------------------------------------------|
| /sethome <название>  | ставит хом в текущей позиции             |
| /delhome <название>  | удаляет хом                              |
| /home <название>     | телепорт к хому                          |
| /homes               | открывает GUI (компасы, клик = телепорт) |

## Права

| Нода            | Описание                           | По умолчанию |
|-----------------|------------------------------------|--------------|
| homes.sethome   | ставить хомы                       | все          |
| homes.delhome   | удалять хомы                       | все          |
| homes.home      | телепорт к хому                    | все          |
| homes.homes     | открыть GUI                        | все          |
| homes.bypass    | снимает лимит хомов (`home-limit`) | op           |

## Лимит хомов

'plugins/HomesPlugin/config.yml':

```yaml
home-limit: 10
```

Общий лимит на всех, без permission-групп — единственное исключение:
игроки с нодой homes.bypass (по умолчанию op) лимит не проверяют вообще.
Перезапись существующего хома (`/sethome` с уже занятым названием) в лимит
не упирается — блокируется только создание нового хома сверх лимита.
Значение не кэшируется в отдельное поле — читается из `plugin.getConfig()`
при каждом вызове `/sethome`. Но сам конфиг в память загружается один раз
при старте, так что правку
файла config.yml всё равно нужно применить через /reload confirm или
рестарт сервера.

## Известные ограничения

- Лимит хомов на игрока — общий для всех через config.yml (см. выше).
  Групповые/permission-based лимиты не реализованы.
- Название хома не может содержать `.` внутри самого YAML-ключа безопасно
  во всех случаях — Bukkit ConfigurationSection API это обходит, но всё
  равно рекомендую не пускать в названия пробелы/спецсимволы на уровне
  команды, если это важно (сейчас не валидируется, кроме длины).
- Мир хома должен быть загружен на сервере в момент телепортации,
  иначе выводится ошибка, а не краш.
